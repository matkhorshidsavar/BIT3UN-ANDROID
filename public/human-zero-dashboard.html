Current Diagnosis

Frontend upstream is not answering on port 3004.

Previous server evidence showed Nginx returning 502 because it cannot connect to 127.0.0.1:3004. The backend PM2 process was online, but no frontend process was listening on that port. Server health was degraded by a large number of zombie processes.

UI/UX Guardrails
  • Error states: use visible text plus role="alert"; never only color.
  • Loading states: show status after 300ms for domain/API checks.
  • Crypto UX: keep fees, network, and irreversible actions explicit.

Runbook
1. Confirm local and public health:
   ./scripts/bit3un-health.sh

2. When SSH is responsive, run Ubuntu/Nginx/PM2 diagnostics:
   BIT3UN_SSH_PASSWORD='...' ./scripts/bit3un-remote-diag.sh

3. Fix path after evidence:
   - If Nginx still points to 127.0.0.1:3004, start the frontend on port 3004 or change Nginx to the real frontend port.
   - Remove duplicate bit3un.ir Nginx server blocks.
   - Restart/reap the parent process creating zombie curl children.
   - Re-run domain, origin, and local checks before declaring the deployment healthy.
